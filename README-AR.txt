منصة MFFT — الحزمة المحدّثة
================================

روابط الموقع بعد النشر
- واجهة الطلاب: https://taha77779.github.io/mfft-learning-platform/
- واجهة الإدارة المنفصلة: https://taha77779.github.io/mfft-learning-platform/#/admin

محتويات الحزمة
- واجهة دخول الطالب بالرقم المعرف ورقم الهاتف.
- إدارة الطلاب: الاسم، الهاتف، العمر، البريد الإلكتروني، وإنشاء رقم معرف فريد.
- الرمز السري الابتدائي هو رقم الهاتف، ويُخزّن في قاعدة البيانات كـ bcrypt hash لا كنص واضح.
- الاختبار النشط الأحدث هو الاختبار الموحد المتاح لجميع الطلاب؛ عند تفعيل اختبار جديد يتم إيقاف الاختبار السابق تلقائياً من الواجهة.
- تعليمات قبل الاختبار، ثم سؤال بصورة أصلية وثماني بدائل.
- خلط مواضع البدائل عشوائياً لكل سؤال وفي كل محاولة.
- لا يظهر مؤقت للطالب. يسجل النظام زمن أول نقرة لكل سؤال ويسجل كل النقـرات والأخطاء.
- النتائج ومحاولات الطالب منفصلة ومرتبطة بحسابه.
- يمكن للمدير السماح بمحاولة ثانية من صفحة النتائج؛ لا يسمح النظام بها دون موافقة المدير.
- الإدارة عبر Supabase Auth، ويجب أن يكون حساب المدير موجوداً في public.admins.
- لا يحتوي المشروع على صور اختبار أصلية؛ يرفع المدير المواد التي يملك حق استخدامها.

مهم قبل تحديث الموقع
1. احتفظ بنسخة احتياطية من قاعدة البيانات الحالية قبل أي تغيير.
2. افتح supabase/mfft_setup.sql واقرأه كاملاً.
3. هذا الملف ترحيل إضافي (Migration) ويفترض أن الجداول الحالية موجودة بهذه الأسماء والأعمدة الأساسية:
   students(id uuid, student_name text, created_at timestamptz)
   tests(id uuid, title text, description text, is_active boolean, created_at timestamptz)
   questions(id uuid, test_id uuid, question_order integer, original_image text, created_at timestamptz)
   question_options(id uuid, question_id uuid, image_url text, is_correct boolean)
   attempts(id uuid, student_id uuid, test_id uuid, started_at timestamptz, completed_at timestamptz, status text)
   answers(id uuid, attempt_id uuid, question_id uuid, first_response_ms integer, total_errors integer, selected_option_id uuid, is_correct boolean, answered_at timestamptz)
   results(id uuid, attempt_id uuid, total_questions integer, total_errors integer, average_response_ms numeric, classification text, created_at timestamptz)
   admins(id uuid references auth.users, full_name text, created_at timestamptz)
4. إذا كان أي اسم عمود مختلفاً، لا تشغّل SQL قبل مواءمته مع مخطط مشروعك. الملف يضيف أعمدة جديدة إلى students وattempts وينشئ student_sessions وanswer_events، ولا يحذف صفوف الطلاب الحالية.
5. بعد التأكد من مطابقة المخطط، شغّل ملف SQL مرة واحدة في Supabase > SQL Editor.
   تنبيه: الطلاب القدامى الذين أُضيفوا قبل هذه الترقية لن يملكوا student_code أو pin_hash؛ أعد إدخالهم من لوحة الإدارة أو جهّز لهم بيانات دخول بطريقة إدارية قبل الاستخدام.
6. تأكد أن Storage bucket باسم mfft-images موجود. يبقى خاصاً، وتسمح السياسة بروابط موقعة للصور. سياسات القراءة والكتابة تُراجع ضمن ملف SQL.
7. تحقق من وجود حساب المسؤول في Authentication > Users ومن وجود صف مطابق له في public.admins.

رفع الملفات إلى GitHub
1. فك ضغط ZIP على جهازك.
2. ارفع محتويات المجلد (وليس المجلد نفسه) إلى جذر مستودع taha77779/mfft-learning-platform على الفرع main، مع استبدال الملفات القديمة.
3. احتفظ بمتغيري GitHub Actions Variables التاليين:
   VITE_SUPABASE_URL = رابط مشروع Supabase
   VITE_SUPABASE_PUBLISHABLE_KEY = مفتاح Publishable
4. لا تضع service_role key في ملفات الموقع أو GitHub Variables المخصصة للبناء.
5. في Settings > Pages اجعل Source = GitHub Actions.
6. افتح Actions وانتظر نجاح Build وDeploy.

طريقة التشغيل
- المدير: افتح رابط الإدارة المنفصل، سجّل الدخول، ثم أضف الطلاب وأنشئ الاختبار وأضف أسئلته.
- الطلاب: يفتحون رابط الطلاب، ويدخلون الرقم المعرف ورقم الهاتف.
- يجب تفعيل اختبار واحد فقط؛ واجهة الإدارة تتعامل مع أحدث اختبار نشط وتوقف الاختبار السابق عند إنشاء/تفعيل اختبار آخر.
- بعد المحاولة الأولى، يستطيع المدير السماح بمحاولة ثانية من جدول النتائج. تتغير مواضع البدائل عشوائياً من جديد.

ملاحظات أمان وقياس
- الرقم المعرف ليس سراً، ورقم الهاتف يُستخدم كرمز سري ابتدائي كما طلبت. يُحفظ hash في قاعدة البيانات، لكن رقم الهاتف قد يكون معروفاً للآخرين؛ الأفضل لاحقاً استبداله برمز عشوائي أو تمكين تغييره.
- رمز جلسة الطالب مؤقت لمدة 12 ساعة، ويُخزن hash الرمز في قاعدة البيانات.
- دوال الاختبار تتحقق من جلسة الطالب، ولا ترسل قيمة is_correct إلى متصفح الطالب.
- روابط صور الاختبار الموقعة تتطلب صلاحية قراءة من Storage؛ أسماء الصور UUID وليست حماية بحد ذاتها.
- لا تنشر بيانات حقيقية قبل اختبار الدخول، إضافة طالب، أداء اختبار، تسجيل الأخطاء، حفظ النتيجة، وإعادة المحاولة بحسابات تجريبية.
- التصنيف إلى مندفع/متروي لا يُصدر آلياً؛ يحتاج إلى معايير معيارية معتمدة ومناسبة للعمر والسياق. المنصة تعرض مؤشرات السرعة والدقة والأخطاء فقط.
- لا يوجد حالياً إرسال تلقائي لرسائل SMS أو بريد إلكتروني للطلاب؛ المدير يسلم الرقم المعرف للطالب يدوياً.
- لا توجد حالياً آلية استعادة جلسة المحاولة إذا أغلق الطالب الصفحة أو حدّثها أثناء الاختبار؛ لذلك اطلب منه عدم تحديث الصفحة، ويجب اختبار هذا السيناريو تجريبياً قبل التطبيق الرسمي.

التحقق
لم نتمكن من تنفيذ npm install / npm run build داخل بيئة إنشاء الحزمة بسبب تعذر تثبيت الاعتماديات في الجلسة. سيقوم GitHub Actions بتثبيت الحزم وبناء المشروع عند رفعه؛ راجع سجل Actions قبل اعتبار النشر ناجحاً.
